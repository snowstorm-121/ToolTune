# T4：冻结 Test、独立 MLX 对照与交付（2026-10-22）

## 首次 Test 前的冻结条件

实验 ID `t4-test-v1`，契约在首次模型生成前写入 `artifacts/t4-test-v1/frozen_contract.json`。冻结 Qwen3-4B-Instruct-2507 同源 MLX 4-bit 基座 revision、13 个模型/tokenizer 文件哈希、T3 Validation 选中的 U200 adapter 哈希、官方 Instruct 模板、数据/解析/评分源码、Test records 与 190 个有序样本 ID、包版本、贪心解码、EOS 停止和 256-token 上限。契约检查实际文件内容，而非仅保存路径。T2 的 65 文件审计和当时 66 项测试在首次 Test 前通过。

Test 是用户在正式模型评测前确认的均衡诊断集：95 个 gold 调用、95 个 gold 非调用，来自 165 个来源对话、163 个连通组。全部调用题只有一个候选工具；95 个非调用题中只有一个带候选工具。总指标不能外推原始 Glaive 分布，工具名指标不能说明复杂多工具路由。无适配工具/明确追问子集没有审定标签，专门指标为 N/A。

## 运行与复算规则

B0 和 SFT 各在独立进程从同一冻结基座加载；B0 检查没有 LoRA 张量，SFT 检查选中 adapter 的 16 个张量。两个臂使用同一 Test 顺序、工具、消息、官方模板、greedy 解码和 256-token/EOS 停止，不使用强制 JSON。目标答案及评分字段不进入生成输入。首次预测逐题写入并 fsync；同一契约只续跑没有记录的 ID，保留错误、截断和空输出，绝不因为结果差自动重试。

严格决策匹配分母是全部 190 题；调用召回、工具名、schema 和参考参数分母都是 95 个 gold 调用。另报生成调用中的 schema 有效率，其分母随模型输出变化。非调用的成功只说明动作未调用，不检验自然语言内容。schema 合法、参数参考匹配、本地执行成功是不同层级。Test 后不依据得分改模型、模板、解析器、指标或输出上限；若以后做修复，原 Test 将标记为已见回归集。

离线复算入口：`PYTHONPATH=src .venv/bin/python scripts/recompute_test.py`。它从两个臂的首次原始预测重新解析和计分，核对全部 190 个 prompt token、保存分数/摘要、来源 ID 和逐题成败转移。完整原始输入、输出、停止原因、系统资源采样和 manifest 留在本地 `artifacts/t4-test-v1/`；Git 只保存适合公开的小型汇总证据。

两个本地只读确定性工具 `sum_integers` 与 `text_length` 只用于“构造的调用文本 → 与评测相同的严格解析器 → schema 校验 → 执行”边界演示，命令 `.venv/bin/python scripts/demo_tools.py`。该命令不运行模型；这些工具不联网、不影响正式 Test 指标，也不把未执行的历史 Glaive API 调用说成执行成功。

主指标净增 **11/190，即 5.79 个百分点**。逐题配对：83 题两者都对，17 题由错变对，6 题由对变错，84 题两者都错。调用子集为 61 / 10 / 5 / 19；非调用子集为 22 / 7 / 1 / 65，顺序同前。没有计算置信区间或显著性；同一来源对话的轮次并非独立样本，这些数只是本次冻结集的描述性结果。

17 个改善中，7 个非调用题只是 B0 在固定 256-token 预算内没结束，而 U200 结束；6 个调用题修复了缺少完整 `tool_call` 包裹；另 4 个调用题的参数与来源参考答案对齐。6 个退化中，1 个非调用题变为截断；调用题有 1 个混入调用前文本导致格式不合法、3 个参考参数不一致、1 个完全未调用。**不能把净增 11 题整体说成更强的工具选择或参数推理。**

B0 的错误类别是截断 72、无效调用包裹 7、参数参考不符 22。U200 仍有截断 66、无效包裹 2、参数参考不符 20、漏调用 2；所有 90 个错题保留在 190 的主指标分母。两个臂在唯一一个 gold 非调用但提供工具的 Test 决策上都未调用；其余 94 个 gold 非调用题没有可用工具，不能凭这里的总分声称充分测试了“有工具但不适配”的拒绝能力。

## 固定样例与失败解释

以下 ID 均在首次原始预测中，可用 `artifacts/t4-test-v1/{baseline,adapter}/predictions.jsonl` 与对应 `scores.jsonl` 复查；展示只是解释指标，没有用于改动 Test 契约。

1. **正确调用** `glaive-v2:112844:a2`：询问 Michael Jackson 的《Thriller》专辑，U200 输出完整 `play_music`，`album` 和 `artist` 与参考参数一致。只证明文本形式的调用正确，没有播放音乐。
2. **格式改善** `glaive-v2:088344:a2`：录制 5 秒音频，B0 给对工具及 `duration=5`，却缺少关闭标签；U200 输出完整包裹。这是格式收益，不能算新的参数知识。
3. **漏调用退化** `glaive-v2:037855:a4`：日历标题和日期已给齐，B0 输出参考 `create_calendar_event` 调用，U200 只说会创建事件，没有实际结构化调用，按漏调用计错。
4. **输出预算与内容边界** `glaive-v2:081350:a2`：用户索要《星夜》主色及比例的 Ruby 代码。B0 长回答被截断；U200 在预算内结束，但给出无法提供代码的拒绝文本。动作指标将其记作改善，因为两者都没有工具可调用；这**不是**问题回答质量改善的证据。
5. **参考答案疑点** `glaive-v2:095636:a4`：来源参考参数含一个明文密码，但可见历史只问算法、用户回答 bcrypt，没有给出该密码。U200 恰好匹配参考字符串，B0 用占位符。分数照冻结参考答案计算；绝不能把这题包装成安全地提取了用户提供的密码。
6. **参数退化与上下文歧义** `glaive-v2:090538:a6`：用户追问 Bill Murray 的电影，U200 在 `actors` 外添加 `genre=comedy`，与参考参数不一致；之前一轮谈过喜剧片，因此该附加条件可能源于上下文，不能直接宣称明确业务错误。相同来源的 `a8` 是一题已有工具响应后的非调用，两臂均正确不再调用。

正式数据没有审定“应追问”标签。Validation 的 `glaive-v2:073945:a2` 可作为**定性**信息不足例：参考答案直接查酒店，模型追问房型；不能据此计算追问准确率。没有把异常输入或人工构造的本地演示混入 Test 分母。

## 资源、核验与边界

B0 的逐题生成累计 **566.71 秒 / 24,686 输出 token**，评测循环约 567.4 秒；U200 为 **602.11 秒 / 23,494 token**，评测循环约 602.8 秒。两臂由独立进程顺序运行、输出长度不同；这些数字不是受控吞吐基准，不能声称 adapter 提速。MLX allocator 累计峰值分别为 **2,752,774,360** 与 **2,766,495,580** 字节，并非整机峰值。系统压力采样：B0 281 次均为等级 1；U200 的 299 次中等级 1 为 279、等级 2 为 20；两臂均未持续红色压力，采样 swap 都是 1,079.56 MiB。没有更改系统内存限制或关闭别的进程。

独立验收 `scripts/verify_t4.py` 重新计算冻结文件哈希；B0 实际加载 0 个 LoRA 张量，U200 加载 16 个。两臂各有 190 条首次预测，所有 prompt token 按 ID 完全相同；原始输出离线重算与逐题分数和总分一致。**68 项 pytest、T2 的 65 文件契约、T4 离线复算全部退出码 0。** 原始错误和退化未重试、未剔除。冻结 Test 从此是已见结果；后续任何修改必须另开实验版本，不能继续把这 190 题当未见验证。
